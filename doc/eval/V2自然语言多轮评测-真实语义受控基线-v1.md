## 实验执行契约

新增内容限 test scope 的 `V2RealModelPilotTest`、`V2ModelCallEvidence` 和测试，以及原测试Harness观察。Production源文件、Prompt、正式Main数据、模型依赖不改。

真实 `ChatOrchestrationService -> V2ChatOrchestrator -> SemanticInterpreter -> OpenAiCompatibleClient`，其后真实Grounding/reducers/compiler/executor/verification/renderer/POST。保留原测试外部事实、隔离持久化和原始用户消息，各场景独立chatId。模型看见的只有解释器实际的system+当前user；即使隔离ChatMemory存有历史，也不偷偷加入模型输入。模型不接收规范、预期ID/答案或归因。

每个run先保存完整Plan和安全metadata，STARTED文件CREATE_NEW防止覆盖。六场景各一次，逐轮保存实际输入/工具schema、原始模型响应、usage/耗时、typed语义、解释器FIRST/REPAIR验证、before/PRE/POST memory、真实事件、实际执行/工具返回和完整回答。记录源文件SHA256、实际输入指纹、配置模型/endpoint/temperature/timeout；不记录API key、HTTP认证头或异常中可能包含的秘密。

Production原有的一次schema/契约repair不删除；runner不追加重试、不选最佳结果。传输失败/可用性错误与semantic contract failure独立分类。缺失响应不补假回答，没执行检查为UNVERIFIED。首轮未形成展示计FIRST_TURN_COVERAGE，后轮历史批次前提失效计BUSINESS_TURN；不把未就绪时的引用错误当语义失败。A/B分别汇总。

三分母严格沿用冻结口径：ready/planned，ready且核心通过/ready，完整充分验收（含充分判定失败）/planned。全36项作为本次保守总体门槛，未验证不能满足；完成率不是成功率。此模式是“真实语义模型+受控上下文”，不是完整端到端检索实验。
