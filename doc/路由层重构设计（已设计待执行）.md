## 2. 根因模型

### 2.1 三轴纠缠一维标签（18 个 isXxx 的生成机制）
route() 输出的路由标签同时编码三件正交的事：
- **语义意图**（换需求 / 追问店铺 / 闲聊 / 元问题）
- **对话状态合法性**（当前状态、此意图此刻是否合法）
- **实体/槽位信号**（位置 / 预算 / 菜系）

一维标签表达三维笛卡尔积 → 每出现新（状态 × 意图 × 槽位）组合就要一个新 isXxx。**isXxx 数量按组合数增长，不是按意图数增长**——这就是 18 个函数还觉得不够的数学原因。

### 2.2 双真相作为"会蔓延的组织病理"
不是孤立失误，是项目缺乏"单一真相来源"强制机制的结果：每个新功能都会自然长出第二份真相。路由层只是最先暴露的地方。

## 3. 目标架构

```
输入: utterance + session(state, working memory)
│
【L0 快速通道】纯代码零 LLM——精确命令词 / 按钮事件 / 系统命令。命中即出，绝不向下传递
│ 未命中
【L1 语义理解层】单次评估 → (intents, slots, confidence)
├─ L1a 意图分类：6 类封闭集（NewRecommendation/DemandSwitch/ShopInquiry/LocationRef/DomainOut/MetaQuestion）
│    embedding 意图例句库（主力）+ 词表（种子/降级路径）
└─ L1b 槽位提取：与意图分类并行独立（位置/预算/菜系/"我附近"指代消解）
     本层不知道也不关心会话状态（学 Rasa：NLU 与 Core 分离）
│
【L2 路由决策层】纯代码状态机转移表
├─ Map<State, Map<Intent|SlotEvent, Action>>，一行一个合法转移
├─ 查表不命中 → 统一降级策略（澄清问题），永不 ERROR
└─ 槽位冲突（显式地名 ≠ 设备城市）在此触发 LOCATION_RESOLUTION（case30 正解）
│
【L3 LLM 兜底分类】仅当 L1 置信度 < 阈值
├─ prompt 只含 6 意图判别标准 + few-shot（含边界反例），绝不包含 L2 状态机规则
├─ 强制结构化输出 {intent, slots, confidence}
└─ 输出进入 L2 状态机裁决——LLM 提议，代码裁决
│
【L4 执行层】不变（PolicyGuard → 硬过滤 → 语义召回 → 排序）——项目最健康的一层，别动
```

**边界一句话版本**：
> 规则（L0/L1a 词表/L2）负责"可枚举的确定性"：精确表述、槽位硬约束、状态合法性——错一个能定位、能测试、能审计；LLM（L3）只负责"封闭集内的低置信语义分类"，且输出必须经状态机裁决才能生效——它波动时最多降级到澄清，永远不会打穿业务约束（硬约束在 L4 无论如何兜底）。

**对应关系**：C = L2 状态机转移表；A = L1a 六意图收敛；B = L3 边界重划（规则判过的不进 prompt）；L1b 槽位独立 = case30 真正解（分层而非压进路由）。

## 5. 为什么不现在执行

1. **freeze 的数据依据**：LLM 兜底占比 20.5% → 4.3%（功能 case 2/46），剩余为真 LLM 领地；词表冻结后路由层进入"不再生长"的稳态。
2. **时间窗口分析**：C 完成后到面试需 ≥3~5 天稳定期（一次全量单测 + 40-case 评测 + 人工 smoke）。面试前一周是 C 的最差时机——回归面是全路由层，修复反应时间最短。
3. **风险/收益比**：C 现在做买叙事完整性（"我把补丁收敛成设计"）；不做带"设计已完成 + 排期合理"去讲同样成立，且多一份判断力证据（"诊断+方案+为什么按优先级暂缓"）。**区别只是叙事里那句话是"我做了收敛"还是"我设计了收敛方案并论证了暂缓"——后者在秋招往往更稀缺。**
